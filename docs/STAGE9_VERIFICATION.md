# 9단계 · 탐지와 회수 제안 확인

현재 단계는 9입니다. 8단계는 사용자가 심판 100점을 확인했습니다.
자료실 주소, 문자열 allowedRoutes, 자료 API의 로그인·소유자 검사, 판정기의 기존 기기·접속·구역 규칙과 XDR 6개를 유지합니다.

src/detect.mjs는 입력을 고치지 않는 순수 함수이며 임의의 권한을 바꾸지 않습니다.
입력에 메모·토큰·실명이 섞여 있어도 허용한 시각·가명 주체·기기·메서드·판정과 상관 항목만 투영합니다.
잘못된 시각·신원, 누락된 기기/네트워크/판정과 클라이언트 헤더는 확정 근거로 승격하지 않습니다.

## 계약 구분

공개 시작 틀의 docs/DETECT_EVENTS.md와 scripts/detect-test.mjs는 at·method·identity.sub 세 항목의 연습 계약입니다.
그 계약의 10분/120건 경계와 subject-only 제안 결과를 보존합니다. 이는 기기별 실제 회수 증거가 아닙니다.
기기·네트워크가 있는 모의 사건은 기존 판정 계약에서 알려진 항목을 사용합니다.
이 확장 입력이 실제 운영 엔진의 새 등록 계약이라고 주장하지 않으며 실제 회수 API를 만들지 않습니다.

복합 사건에서는 같은 주체·기기·반·프로젝트의 낯선 네트워크 조회가 10분 구간에 120건을 넘을 때만 해당 deviceId 한 개를 제안합니다.
평소 네트워크의 다량 조회, 낯선 네트워크의 120건 이하, 지역 하나, 여러 기기 합계, 출처 불명/누락은 observe입니다.
사건 시각을 정렬하고 이동 구간을 계산하므로 입력 순서나 정각 경계에 의존하지 않습니다.
requestId가 있는 경우 중복을 한 번만 세고 충돌은 제외합니다. 회수 제안은 기존 burst_read 이유 코드를 사용합니다.

## 재현

```sh
npm run detect:test
node --test test/stage9-detect.test.mjs
npm run decider:test
npm test
npm run bundle
```

탐지 연습 12건과 새 시험 8개는 정상·복합 사건, 120/121건과 10분 경계, 다른 주체/기기/범위,
비밀값 제외, 순서/중복/충돌, 의심 기기 한 개와 정상 기기 보존, 단독 VM 실행을 확인합니다.
제출 묶음은 기존 구역 검사와 탐지 연습을 한 자기 점검으로 기록해 기존 최대 20개 제출 계약을 유지합니다.
배포 식별 정보의 9단계·커밋·경로와 실제 공개/무로그인 거부 응답을 다시 점검합니다.

운영 사건의 실제 전달, 회수된 신원/탈취 세션/다른 자원으로의 재접속 차단과 경과 시간은 여기서 실행하지 않았습니다.
이 부분은 심판 판정으로 확인하며 정상 기기의 권한을 변경하거나 회수 완료 시간을 지어내지 않습니다.
