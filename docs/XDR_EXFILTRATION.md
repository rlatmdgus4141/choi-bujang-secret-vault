# XDR 06 · 자료 반출 탐지와 목적지 차단 후보

8단계는 보류 중입니다. 기존 자료실, 로그인·소유자 검사와 `src/decider.mjs`의 정책은 변경하지 않습니다.

`read-alerts.mjs`는 공식 경보 30건을 시각·출발 주소·계정·규칙 수준·설명 다섯 항목으로만 투영합니다.
키·JWT·비밀번호처럼 보이는 값은 자르기 전에 가립니다. 원본 경보는 보존하며 이 모듈을 판단기가 불러오지 않습니다.
`decide.mjs`의 패턴은 `patterns.json`과 동일한 상단 상수입니다. import, 파일 접근, 네트워크 조회와 이전 경보 상태 없이 한 건마다 즉시 답합니다.

## 근거와 판단 정책

- [MITRE T1041](https://attack.mitre.org/techniques/T1041/): 기존 명령 통로로 자료를 반출하는 기법.
- [MITRE T1048](https://attack.mitre.org/techniques/T1048/): 다른 프로토콜을 이용하는 반출 기법.
- [MITRE T1560](https://attack.mitre.org/techniques/T1560/): 전송 전 자료 압축. 압축 파일 생성만으로 반출 성공을 단정하지 않습니다.

50,000,000바이트(십진수 50MB), 반복 5회, 비정상 포트의 파일 30건, 전체 복사의 100건은 학습용 정책입니다. MITRE의 고정 임계값이 아닙니다.
실제 전송량과 목적지, 경보의 새 목적지·반복·업무 시간 밖 압축 반출·비정상 통로/짧은 시간 전체 복사 신호가 함께 있어야 차단 후보입니다.
규칙 수준이나 기법 번호 하나만으로 차단하지 않습니다. 전송 실패·전송 없음·승인된 백업·용량 부족·숫자 불일치·형식 오류는 자동 차단하지 않습니다.
누락된 평소 목적지나 시간대를 임의로 채우지 않고, 업무 시간 여부는 신뢰된 경보 요약으로만 확인합니다.

확신도 0.85 이상은 block, 0.5 이상은 alert, 나머지는 record입니다. 사유는 패턴 이름과 고정 문구 한 줄이며 경보 원문을 반사하지 않습니다.

## 재현과 관찰 결과

```sh
npm run xdr:exfiltration:read
npm run xdr:run -- exfiltration
npm run xdr:exfiltration:respond
node --test test/xdr-exfiltration.test.mjs
```

공식 경보 30건의 판단은 block 10 · alert 10 · record 10입니다. 정상 경보 10건 중 block은 0건입니다.
가상 사건 시각으로 연결을 재생하면 차단 후보 10건만 목적지 거부 규칙을 만들고 정상 요청 10건은 그대로 통과합니다.
격리 VM에 `decide.mjs` 한 파일만 올려도 같은 결과이며 새 주소·계정·영문 설명·경계 용량·실패·만료·중복·동시 전달도 시험합니다.
이 결과는 자기 점검이며 실제 심판 결과가 아닙니다.

## 대응 범위와 운영 연결의 한계

`respond.mjs`는 스스로 판단을 다시 계산하고, 유효한 목적지 IP·근거 ID·5분 이내의 새 경보에 대해서만 15분 만료 규칙을 만듭니다.
규칙은 `xdr/runtime/exfiltration-deny-rules.json`에 별도로 보관합니다. 동일 경보를 재전달해도 만료를 연장하지 않습니다.
`xdr/alerts.log`에는 선택한 감사 항목만 쌓고 계정·전송 원문·비밀번호·토큰은 기록하지 않습니다. 런타임 규칙과 로그는 Git에서 제외됩니다.
출발 주소나 계정을 격리하지 않으며, 상대 목적지의 만료된 규칙은 적용하지 않습니다.

`createVaultXdrGate`는 기존 판정기에 추가 거부 확인을 연결하는 부품입니다. 차단 대상 목적지는 서버가 확인한 `trustedDestinationIpForRequest` 콜백으로만 받습니다.
요청 본문·헤더의 주소는 믿지 않습니다. 차단 대상이 아니면 기존 요청과 판정을 그대로 보존합니다.
현재 18항목 엔진 계약에는 목적지 IP와 XDR 거부 사유 등록 계약이 없습니다. 운영 연결에는 신뢰된 서버 목적지 매핑과 등록된 거부 응답 콜백이 필요합니다.
현재 재생은 시험용 기본 정책과 가상 시계로 한 연결 시험입니다(`simulated: true`, `liveEngineConnected: false`). 실제 운영 엔진·네트워크 방화벽 집행은 미검증입니다.
자료실 화면과 DB를 변경하거나 정상 사용자의 모든 자료 요청을 막지는 않습니다.
