# 5단계 검증 기록과 재현 절차

5단계 첫 제출은 조건 7개 충족, 완결성 가점 1개, 80점입니다(사용자 제공 판정).
완결성 가점 세부 기준은 확인하지 못했습니다. 아래 보완은 제출 검증과 재현성 개선이며,
추가 점수 획득이나 실제 계정 시험 완료를 뜻하지 않습니다.

## 이번 보완

- 실패한 실제 요청 점검을 성공한 제출 파일로 만들지 않도록 생성 절차를 강화합니다.
- 배포 커밋과 단계 외에도 로그인 발급자, 허용 API 경로, 원본 자료 경로를 대조합니다.
- 이미 적용한 권한 회수 SQL과 읽기 전용 권한 확인 SQL을 저장소에 함께 둡니다.
- 전체 구조 재현 SQL에서도 열 단위 권한이 남으면 성공으로 처리하지 않습니다.

보완 후 로컬 시험 23개가 통과했습니다. 실패 응답과 오래된 배포 설정을 거부하는 회귀 시험을 포함합니다.

## 2026-10-06 추가 확인

- DB 권한을 읽기 전용 SQL로 다시 확인했습니다. `stage5_permissions_ok` 및 다섯 세부 값은 모두 true이며 메모 4건·RLS 정책 4개가 유지됩니다.
- 검증용 클라우드 브라우저에서는 무로그인 화면에 메모가 보이지 않았습니다.
- 보안 로그인 입력은 제출됐으나 화면에 「인증 서버에 연결하지 못했습니다」가 표시되어 A/B 자동 화면 시험은 완료하지 못했습니다. 입력값은 읽거나 기록하지 않았습니다.
- 사용자는 본인 브라우저에서 A 로그인·시험 메모 추가·수정·삭제가 정상 동작한다고 확인했습니다. 이는 사용자 수동 확인이며 에이전트의 실제 HTTP 자동 시험과 구분합니다.
- B의 본인 CRUD와 상대 메모 ID를 지정한 요청, 로그인 토큰을 동반한 원본 API 요청은 아직 이번 단계에서 실행 결과를 얻지 못했습니다.

학생 매뉴얼은 요구 기능·거부와 예외 처리·확인 근거를 완결성 요소로 설명하지만,
5단계 가점의 개별 기준은 제시하지 않습니다. 이번에는 실제로 확인한 근거만 보완하며,
이 기록이 가점으로 인정되는지와 100점 달성 여부는 심판의 재판정으로 확인해야 합니다.

## 다시 확인하는 순서

1. 코드 확인: `npm ci && npm test && npm run check:stage2`.
2. 커밋이 Production에 배포된 후 `npm run check:stage2 -- --deployed`.
3. Supabase SQL Editor에서 `supabase/verify-stage5.sql` 전체 실행.
   `stage5_permissions_ok` 및 다섯 세부 확인 값이 모두 true여야 합니다.
4. 아래 A/B 수동 확인을 수행하고 성공/실패만 기록합니다. 토큰이나 비밀번호는 공유하지 않습니다.
5. `npm run bundle`로 현재 커밋의 제출 파일을 생성합니다.
   실패하면 첫 오류를 해결하고 같은 명령을 다시 실행합니다.
   실패 전에 만들어 둔 예전 JSON을 새 배포의 결과로 제출하지 않습니다.

## A/B 화면 수동 확인

1. 일반 창에서 A 로그인: 기존 본인 메모 3건 확인.
2. 새 시험 메모 1건을 추가하고 제목·본문을 수정한 뒤 그 시험 메모만 삭제.
   새로고침 후 사라졌는지 확인. 기존 메모는 삭제하지 않습니다.
3. 시크릿 창에서 B 로그인: 기존 본인 메모 1건 확인. B도 같은 추가·수정·삭제 수행.
4. 두 창에서 상대의 목록이 보이지 않는지 확인. 이는 목록 분리 확인이며,
   다른 메모 ID를 지정한 교차 요청의 실제 시험과는 구분합니다.
5. 로그아웃 뒤 메모가 사라지고 /api/notes를 열면 자료 없는 401 오류인지 확인.

## DB 파일의 용도

| 파일 | 용도 | 실행 여부 |
| --- | --- | --- |
| supabase/schema.sql | 새 학습 DB 구조와 5단계 권한 재현 | 새 환경에서만 검토 후 실행 |
| supabase/stage5-lockdown.sql | 기존 학습 notes 테이블의 직접 권한 회수 | 사용자가 이미 실행한 SQL, 이번에 다시 실행하지 않음 |
| supabase/verify-stage5.sql | 현재 테이블·열 권한, RLS, 서버 CRUD 확인 | 읽기 전용, 언제든 재확인 가능 |

문제가 생겨도 인증이나 소유자 검사를 끄거나 authenticated에 직접 권한을 다시 주지 않습니다.
우선 첫 오류와 현재 배포 커밋을 확인합니다. DB 자료를 삭제하거나 Git 이력을 강제로 되돌리지 않습니다.
