# 12단계 탈환 작전실

## 근거와 범위

11단계는 사용자 심판 결과 100점으로 확인했습니다. 학생 코드는 제공 엔진을 대체하지 않습니다.
화면의 성공 문구는 판정 근거가 아니며, 12단계와 공식 41종 공격 결과는 운영 심판이 정합니다.
공식 공격 목록·개별 실행 결과를 전달받는 계약이 없어 41종은 `unexecuted`, 확인된 수는 0으로 둡니다.
이 값은 실패 41건이나 방어율 0%라는 뜻이 아닙니다. 이전 단계 100점을 41종 통과로 환산하지 않습니다.

| 출처 | 구현/책임 | 확인 범위 |
|---|---|---|
| 운영 측 제공 ALEPH SDP 엔진 | 신원·기기 인증, 요청 전달, 운영 신원 회수, 심판 공격 | 엔진 내부 코드를 재포장하지 않음; 운영 회수와 41종 결과 미연결 |
| 공식 시작 틀 ChoiTimo/aleph-defense-starter | 판정·탐지 입출력 계약, 로그인 검증 도우미 | 기존 계약과 verify-login.mjs 보존 |
| 학생 구현 | 판정 규칙·탐지·자료실 API·원본 접근 제한·사본 복구·설치형 접속 앱·작전실 | 저장소 현재 커밋과 보고서의 commit을 대조 |

## 화면과 API

같은 자료실 아래 「탈환 작전실」에서 다음 세 범위를 따로 표시합니다.

- 배포 API 실측: 실제 HTTP 요청의 상태 코드와 서버가 생성한 요청 ID·확인 시각.
- 가상 API 연동: 실제 클라이언트 암호화·API 핸들러를 실행하지만 DB·계정·토큰은 시험 대역. 운영 실측이 아님.
- 미실행: 실제 계정의 다른 소유자·DB 복구, 운영 엔진 추가 확인·탐지·회수·서명 공격과 공식 41종 개별 결과.

`GET /api/operations`는 공개 소프트웨어 메타데이터만 반환합니다. 규칙 ID, 배포 커밋, 정책/메모 사본 버전과 미연결 상태를 반환하며 사용자·기기 목록·메모·토큰을 조회하지 않습니다.
`/operations-verification.json`은 배포 빌드에서 실행한 가상 통합 결과입니다. 화면은 이 보고서와 `/aleph.json`, 메타데이터 API의 커밋이 같아야 표시합니다.
운영 탐지 사건이나 회수 결과가 없는 상태를 가상 사건으로 채우지 않습니다. 가상 탐지의 회수 **제안**과 기기 등록의 회수 시험, 운영 신원 회수를 구분합니다.
복구 버전은 정책 사본 메타데이터와 API의 `stage10-v1` 계약입니다. 현재 운영 DB가 복구됐다는 뜻이 아닙니다.

## 1~11단계 검증표 만드는 절차

1. `npm run ops:check`: 같은 가상 실행에서 무인증/타인 접근, 정상 CRUD, 승인 전 거부, 무서명·경로/본문 변조, 사본 복구 직후 무서명 변경 거부와 정상 조회, 기기 회수 뒤 재접속 거부를 검증합니다. 기존 정책/탐지와 복구 회귀도 실행합니다.
2. 배포 뒤 `npm run ops:live`: 현재 로컬 커밋과 배포 커밋을 먼저 대조하고, 공개 메타데이터 정상 GET(200)과 금지 PUT(405), 무인증 보호 API(401)를 실제 전송합니다. 결과는 `artifacts/operations-live.json`입니다.
3. 화면 「공개 API 점검」은 같은 정의를 사용합니다. 기존 보호 자료에 쓰기나 삭제를 하지 않습니다.
4. 실제 계정 로그인 → 「이 접속의 기기 승인 요청」 → 「내 승인 기기로 읽기 점검」: 본인 목록 정상(200), 같은 로그인으로 서명 없는 요청 거부(403)를 실제 측정합니다. 응답 본문은 표나 내려받기 파일에 포함하지 않습니다.
5. 표의 단계·요청·범위·기대·실제·요청 ID·확인 시각을 비교합니다. 서버 헤더 누락, 연결 실패, 예상 밖 HTTP 상태는 통과가 아닙니다. 「가린 결과 내려받기」는 사용자가 누를 때만 현재 표를 저장합니다.
6. A/B 실제 접근·운영 엔진 시험은 해당 시험 계정/공식 엔진 경로에서 별도 수행해야 합니다. 공개 점검으로 인증된 타인 접근까지 검증했다고 쓰지 않습니다. 공식 원본 결과를 얻기 전까지 41종 결과는 미실행입니다.

## 서버 기록 대조와 개인정보

메모·공지·기기·복구·작전실 API는 응답에 `X-Vault-Request-Id`, `X-Vault-Checked-At`을 붙입니다.
Vercel 운영 런타임은 **같은 값**으로 `aleph.api.observation.v1` 구조 기록을 남깁니다.
기록은 요청 ID, UTC 확인 시각, 허용된 HTTP 메서드, 경로 종류, 상태 코드만 포함합니다.
개별 메모 ID는 `:id`, 알 수 없는 경로는 `/api/other`로 가리고 쿼리·본문·헤더·실명·소유자·토큰·키를 기록하지 않습니다.
운영 로그에서 요청 ID로 검색하여 화면 상태 코드/시각을 대조합니다. 로그 조회 권한이 없으면 직접 대조 미실행으로 기록합니다.
표는 현재 페이지 RAM에 있으며 자동으로 브라우저 저장소에 쓰지 않습니다. 메모 본문이나 인증 자료는 CustomEvent에 넣지 않습니다.
서버의 기존 인증·서명·소유자 검사 순서와 응답 본문은 그대로이며 작전실을 통해 보호 자료를 우회 조회할 수 없습니다.

## 실행 기록

실제 실행 결과는 명령 출력, 배포의 커밋 연결 보고서, artifacts의 배포 실측 결과를 기준으로 합니다.
화면의 표를 외부에서 수정해도 권한과 공식 심판 결과는 바뀌지 않습니다.
브라우저 로그인 시험과 41종 심판 결과는 사용자가 실행/전달하기 전까지 미실행입니다.
