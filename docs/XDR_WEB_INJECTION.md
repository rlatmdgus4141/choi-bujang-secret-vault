# 보너스 xdr-02: 웹 주입 공격 탐지

## 입력과 근거

기본 브랜치 main에 원래 있던 공식 `xdr/fixtures/web-injection.json` 26건을 그대로 사용합니다.
Git blob은 `c1e6b7f2d226c5f85e09e026f726fdcb8fd7eff1`입니다. 실행기 `scripts/xdr-run.mjs`도 변경하지 않았습니다.
이 자료는 가상 경보이며 URL의 문서용 표식을 실제 공격 문자열로 간주하지 않습니다.
판단은 경보 ID·가상 계정·고정 주소·문서용 표식으로 정답을 구분하지 않습니다.

- 공통 과제 근거: https://attack.mitre.org/techniques/T1190/
- 스크립트 주입 형태: https://owasp.org/www-community/attacks/xss/
- 경로 순회 형태: https://owasp.org/www-community/attacks/Path_Traversal
- 명령 주입 형태: https://owasp.org/www-community/attacks/Command_Injection

T1190은 외부 공개 앱 취약점 악용 범주입니다. 모든 스크립트 주입이 곧 T1190 초기 접근 성공인 것은 아닙니다.
각 패턴의 이름·조건·근거는 `patterns.json`에 있으며 `decide.mjs` 맨 위에 같은 상수로 들어 있습니다.

## 판단 정책

SQL 조건식/문장 연결, 스크립트 태그/이벤트 속성, 두 단계 이상의 상위 경로, 명령 구분자와 명령 구문을 찾습니다.
실제 URL은 길이를 제한하고 최대 두 차례 퍼센트 디코딩한 뒤 문자열로만 검사합니다. 입력을 실행하지 않습니다.
공식 경보처럼 원문이 대체된 경우에는 Wazuh 상관 경보의 SQL·스크립트·경로 이탈·명령 주입 설명을 사용합니다.
`select`, `script`, `up`, 따옴표나 세미콜론 하나만으로 차단하지 않습니다.

차단에는 유효한 출발 주소, 웹 요청 주소, T1190 표식, 규칙 수준 10 이상, 같은 출발 주소의 반복 주입 요약이 필요합니다.
`data.count`는 신뢰된 Wazuh가 해당 출발 주소에 대해 집계한 시도 수로 해석합니다. 5건 이상을 자동 차단 후보 기준으로 둡니다.
이 수치와 5분 시간 창은 학습용 정책이며 MITRE의 지정 기준이 아닙니다.
설명과 count가 충돌하거나 반복이 없다고 명시되면 자동 차단하지 않습니다.
시간 창이 제공되면 5분 이내여야 하며, 시간 창이 없을 때는 이미 상관된 높은 수준의 경보만 사용합니다.
단일 경보를 파일이나 전역 상태에 쌓아 반복 증거를 만들어 내지 않습니다.

확신도 0.85 이상은 block, 0.5 이상은 alert, 나머지는 record입니다.
원문 공격 표현이 있더라도 단발성/낮은 수준/상관 증거 부족이면 알림으로만 남깁니다.
T1190 의심 경보에 구체적 패턴이 없으면 사람이 확인할 알림이며, 정상 저수준 조회는 기록합니다.
reason은 고정된 패턴 이름과 짧은 설명이고 원문 URL·계정·키·토큰은 넣지 않습니다.

## 모듈 분리와 기존 규칙 보존

- `read-alerts.mjs`: 시각·출발 주소·계정·규칙 수준·설명만 뽑습니다. 비밀값 형태는 가립니다. 26건 → 26줄입니다.
- `decide.mjs`: `decide(alert)`만 내보내며 import·네트워크·파일 입출력·시계·누적 상태가 없습니다.
- `respond.mjs`: 판단을 다시 계산하고 신선한 차단 후보만 별도 임시 거부 규칙에 넣습니다.
- 규칙: `xdr/runtime/web-injection-deny-rules.json`, 유효 시간 15분, 출발 주소와 근거 경보 ID 포함.
- 알림: `xdr/alerts.log`에 한 줄 JSON으로 기록합니다. 원본 설명·URL·계정·자격 증명은 기록하지 않습니다.
- 5분이 넘은 경보, 미래 경보, 잘못된 주소나 경보 ID로 차단 규칙을 만들지 않습니다. 중복 전달은 만료를 연장하지 않습니다.
- 만료 규칙은 요청 판정에서 제외합니다. 파일 갱신은 프로세스 안에서 직렬화하고 원자적으로 교체합니다.

`createXdrGate(baseDecide, options)`는 유효한 추가 거부 규칙이 없으면 기존 요청과 기존 판정을 그대로 유지합니다.
`createVaultXdrGate(options)`는 변경하지 않은 `src/decider.mjs`에 연결합니다.
IP는 별도 신뢰된 서버 측 제공자로 전달해야 하며 임의 request 필드·사용자 헤더·본문을 신뢰하지 않습니다.
응답의 이유 코드는 운영 등록부와 맞는 값을 호출자가 제공해야 합니다.
기존 무차별 로그인 모듈과 규칙 파일은 보존했으며 두 gate를 합성해 기존 차단을 유지할 수 있습니다.

현행 18필드 엔진 계약에는 IP가 없고 기본 판정기는 아직 starter.deny입니다.
현재 운영 Wazuh/반 엔진/PC 방화벽에 연결하거나 운영 요청을 허용하도록 바꾸지 않았습니다.
정상 허용 검증은 시험용 기본 정책을 두고 수행했으며 실제 기본 거부 규칙을 그대로 전달하는 시험도 있습니다.
로컬 파일 저장 방식은 다중 서버 동기화나 Vercel 영속 저장을 제공하지 않습니다.

## 재실행과 검증

```sh
npm run xdr:run -- web-injection
npm run xdr:web:respond -- web-injection
npm run test:xdr
```

공식 경보 결과: **block 8 · alert 9 · record 9**.
경보 시각을 가상 시계로 재생한 연결 시험: 명확한 후보 8건 거부, 정상 9건 중 추가 차단 0건.
시험은 원본 해시, 패턴 상수 일치, 입력·순서 독립성, 단독 VM 실행, 일반 검색어와 단발 요청의 비차단,
인코딩된 입력, 충돌하는 횟수, 규칙의 만료·중복·동시 갱신, 비밀값 가림, 기존 판정 보존을 확인합니다.
이는 로컬 검증 결과이며 심판 점수나 실제 운영 오탐률을 의미하지 않습니다.
