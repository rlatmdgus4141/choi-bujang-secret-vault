## 4. 학생 PC의 새 폴더 실행 순서

1. 원래 폴더와 그 Git 기록·개인 설정을 그대로 둡니다. 새 대상 폴더가 이미 있으면 그 폴더를 삭제하거나 덮어쓰지 않고 다른 새 이름을 사용합니다.
2. 저장소 URL·브랜치·선택할 40자리 커밋을 먼저 기록하고 새 폴더로 clone합니다. GitHub에 없는 커밋이라면 원본 로컬 Git 폴더를 대상으로 한 clone도 가능하지만, 이번 안내는 GitHub에 올라간 위 커밋을 사용합니다.
3. 새 복제본에서 실제 HEAD를 출력해 선택한 커밋과 대조합니다. Node·Git 버전과 확인 시각을 함께 기록합니다. 앱에 외부 npm 의존성이 없으므로 임의 설치·업데이트를 추가하지 않습니다.
4. `on-client`에서 21단계 설명서의 예제 실행 도구를 사용합니다. 원래 앱의 5189를 유지하려고 새 복제본은 제공 옵션 `-Port 5192`를 사용합니다. 이 포트 옵션의 Windows 실행은 학생이 실제 출력으로 확인해야 합니다.

```powershell
Set-Location "$env:USERPROFILE\keshev-defense-repro-22\on-client"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo -Port 5192
```

5. 새 브라우저 주소 [http://127.0.0.1:5192/](http://127.0.0.1:5192/)를 엽니다. 기존 5189 화면과 혼동하지 않습니다. 예제 모드는 계정 연결 설정을 자동 준비하지 않으며 원래 인증 파일을 복사하지 않습니다.
6. 확인한 화면과 상태, 확인 시각을 실제 관찰대로 기록합니다. 보지 않은 기능·실제 연결·유료 설명·집행·OSV 결과는 미확인으로 유지합니다.
7. **새 복제본을 실행한 창**에서 Ctrl+C로 종료한 뒤, 같은 폴더에서 위 명령으로 다시 실행하고 같은 주소를 엽니다. 원래 폴더의 서버를 임의 종료하지 않습니다.
8. 실제 학생 결과를 문서에 반영해 22단계 커밋을 생성합니다. 문서 갱신 후 생성된 최종 커밋을 또 다른 새 폴더에 고정해 실행·종료·재실행을 확인해야 합니다. 현재 표의 21단계 기준 결과만으로 이 마지막 확인을 완료했다고 쓰지 않습니다.

## 5. 최종 커밋 결속과 남은 확인

최종 제출값은 실제 `git rev-parse HEAD` 출력으로 확인합니다. 문서 안에 미래 커밋 해시를 예상해 넣지 않습니다. 최종 커밋을 새 폴더로 받은 뒤의 실제 HEAD·환경·실행 시각·관찰 결과도 보존해 포털 제출 커밋과 대조합니다. 문제 수정으로 커밋이 바뀌면 새 커밋으로 다시 확인하고 이전 커밋의 결과를 새 결과로 바꾸지 않습니다.

현재 남은 항목은 학생 Windows 새 폴더 실행, 최종 제출 커밋 자체의 새 폴더 확인, 실제 SDP·AI 게이트·조치 집행·외부 OSV의 기다림(UNV)입니다. 서버 AI의 원문 검토 통과는 이 미완료 항목의 실행 성공·실제 운영 인증·v1.0 자동 인증이 아닙니다.
