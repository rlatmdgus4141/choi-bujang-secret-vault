## 2. 옮길 파일과 설정 경계

Git clone으로 커밋된 `on-client` 코드·학생 문서·제공 설정 견본과 기존 프로젝트 이력을 가져옵니다. 소스 경로는 저장소 상대 경로와 `$env:USERPROFILE` 기준으로 안내하며 특정 사용자의 로컬 절대경로를 이식 조건으로 삼지 않습니다.

`on-client`의 실행에는 Node 기준 24.19.0이 필요하며 현재 외부 npm 의존성은 없습니다. 브라우저 주소의 호스트는 loopback입니다. 새 폴더에서는 원래 서버를 보존하기 위해 5192를 사용할 수 있습니다. 다른 환경·포트 옵션의 성공 여부는 해당 환경의 실제 출력으로 확인합니다.

개인 계정 설정·인증서·키·보관소를 clone에 덧붙이지 않습니다. `.env.example`은 비밀 없는 견본이며, 실제 자격이나 설정 적용 성공을 뜻하지 않습니다. 새 프로젝트 경로는 기존 개인 보관소와 결속이 다를 수 있으므로 원래 설정을 그대로 복사하면 안 됩니다. 필요한 실제 계정 연결은 제공 승인 흐름과 담당자 절차로 따로 수행하고 결과를 확인합니다.

## 3. 데이터 보존·백업·복원 계획

아래는 **계획**입니다. 실제 학생 DB·개인 자격·운영 시스템의 백업·복원을 실행한 기록은 없습니다. 학생 데이터가 보존됐다는 주장도 실제 검사 없이 하지 않습니다.

| 대상 | 보존·백업 절차 | 복원·확인 절차와 제한 |
|---|---|---|
| 커밋된 코드·학생 문서 | 원래 작업 폴더를 유지하고 특정 커밋을 원격에 보관합니다. 별도 폴더 clone으로 커밋 원문 사본을 만듭니다. | 새 폴더에 선택한 커밋을 고정하고 HEAD·버전·필수 파일·실행 절차를 대조합니다. 원래 폴더를 reset·삭제·덮어쓰지 않습니다. |
| 미커밋 학생 작업 | 이동 전 Git 상태와 준비된 파일 목록을 먼저 읽습니다. 비밀 없는 학생 소스·문서는 별도 사본 또는 범위를 확인한 커밋으로 보존합니다. | 새 폴더의 기준 코드와 변경을 먼저 비교하고 필요한 학생 파일만 반영합니다. 다른 작업을 일괄 stage하거나 기존 staged 변경을 버리지 않습니다. |
| 로컬 화면 상태 | 필터·선택한 상세·대기 중 결과는 현재 입력으로 다시 그립니다. 일시적인 표시 상태를 업무 원본 데이터의 백업으로 취급하지 않습니다. | 새 입력·새로고침·새 서버 실행에서 다시 조회합니다. 과거 성공 표시를 현재 결과로 복원하지 않습니다. |
| 개인 계정 설정·AI 자격 보관소 | 시작 도구가 프로젝트 밖의 개인 보관 경로와 소유권·접근 제어를 사용합니다. 학생이 이를 Git·ZIP·문서에 복사하지 않습니다. | 다른 경로·PC에서는 담당자가 승인한 보호된 백업·복원 또는 새 승인 절차를 사용합니다. 기존 파일 복사만으로 계정 연결이 복원됐다고 보장하지 않습니다. |
| SDP·XDR·기존 자료실 데이터 | 원천 시스템과 기존 자료실 DB는 그대로 보존합니다. clone이나 화면 확인을 이유로 schema·seed·삭제 SQL을 실행하지 않습니다. 원천 백업은 담당자의 승인된 일관된 스냅샷 절차를 사용합니다. | 학생·프로젝트·권한 연결을 확인한 환경에서 원천 담당자가 복원·검증합니다. 현재 실제 DB 경로·백업 파일·복원 결과는 미확인입니다. |
| 조치 영수증·감사 기록 | 제공 조치 저장소는 별도 기존 SQLite 파일과 원천 집행기 계약을 사용합니다. 경로와 운영 집행이 준비되지 않았으므로 학생이 DB를 만들거나 덮어쓰지 않습니다. | 담당자는 기록·WAL 등 일관성과 최신 처리 상태를 보존하는 절차를 먼저 정합니다. 오래된 DB 사본으로 실행 기록을 지우거나 자동 재집행하지 않습니다. unknown은 기존 요청 ID로 결과만 확인합니다. 실제 복원은 UNV입니다. |
| 패키지 조회 대상·lock | 담당자가 승인한 대상 프로젝트의 lock과 설정을 따로 관리합니다. 회사·비공개 패키지나 개인 경로를 제출물·외부 조회로 내보내지 않습니다. | 실제 설치 메타데이터와 lock이 맞는지 다시 확인한 뒤 승인된 공개 패키지만 조회합니다. 20단계 가상 시험 결과를 실제 OSV 복원 증거로 사용하지 않습니다. |
| 재현 증거 | 저장소·커밋·버전·환경·확인 시각·관찰 결과를 구분해 보관합니다. 제출 문서에는 비밀 없는 요약만 반영합니다. | 최종 제출 커밋과 실행 로그의 HEAD를 대조합니다. AI 검사, 예제 시연, 학생 진술, 공식 원문 판정을 서로 다른 증거로 유지합니다. |

현재 확인한 보존 범위는 AI가 만든 새 Git 복제본의 작업 트리가 검사 전후 깨끗하게 유지됐다는 것뿐입니다. 이것은 학생 PC의 미커밋 작업·개인 보관소·운영 DB 백업/복원 검증이 아닙니다.

## 4. 미완료 사항과 지원 범위

- 실제 직원 계정의 SDP·XDR 연결과 본인 자료 응답: 미확인·기다림(UNV).
- 실제 AI 앱 승인·모델 목록·유료 사건 설명: 미확인. 반복 유료 요청으로 확인하지 않습니다.
- 실제 학생 권한·대상에 대한 조치 집행과 효과 재조회: 원천 연결 미완료, 기다림(UNV). 운영자 담당이어도 전체 목표에서 제외하지 않습니다.
- 실제 승인 프로젝트의 OSV 외부 조회: 미확인. 예제·미조회·부분 실패를 취약점 없음이나 앱 안전 보장으로 바꾸지 않습니다.
- 학생 Windows 새 폴더 실행·브라우저·종료·재실행과 최종 22단계 커밋의 재확인: 실제 학생 결과 입력 전입니다.
- 다른 PC·다른 운영체제의 전체 실행·자격 이식·데이터 복원: 미확인입니다.

이 항목이 남아 있으므로 검증 중 버전으로 기록합니다. 확인되지 않은 항목을 완료로 올리거나 AI 원문 검토를 실행 성공 증명으로 표현하지 않습니다.

## 5. 최종 제출 순서

학생의 실제 결과와 확인 시각을 재현 기록에 반영하고, 이번 문서와 앱 코드가 포함된 커밋을 만듭니다. 기존 staged 작업은 먼저 목록을 확인하고 보존합니다. 새 커밋이 만들어지면 그 정확한 값을 새 복제본에 고정해 다시 실행합니다. 문제를 고쳐 커밋이 바뀌면 새 커밋 기준으로 다시 기록합니다.

21·22단계는 [과제 화면](https://aleph-omega.vercel.app/defense#alekovPortal)에 저장소 주소와 실제 40자리 커밋을 직접 입력합니다. 공개 GitHub에 해당 커밋이 있으면 원문을 읽을 수 있습니다. 비공개 저장소는 공개로 바꾸지 않고 과제 화면의 원문 전달 도구를 사용합니다. 실제 도구 위치·출력 폴더·최종 해시가 확인되지 않았으므로 임의의 구체 명령이나 실행 완료를 기록하지 않습니다.

원문 전달만 실패하면 기존 접수를 유지하고 원문만 다시 보내기를 사용합니다. 접수·원문 전달 완료·AI 판정 통과·실제 실행 검증은 별개입니다.
