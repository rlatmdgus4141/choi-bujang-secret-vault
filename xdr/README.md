# XDR 보너스 경보

이 폴더는 보너스 여섯 개의 연습 경보입니다. 경보는 수업용으로 만든 Wazuh 모양이며, 실제 로그가 아닙니다. 정답은 이 저장소에 없습니다.

## 경보 묶음

`xdr/fixtures/<moduleKey>.json` 을 읽습니다. `moduleKey` 는 아래 여섯 개입니다.

| moduleKey | 보는 것 |
|---|---|
| `brute-force` | 짧은 시간에 몰린 로그인 실패 |
| `web-injection` | 웹 요청에 섞인 주입 형태 |
| `known-cve` | 이미 공개된 취약점을 노린 요청 형태 |
| `persistence` | 다시 켜도 남도록 심긴 서비스·예약 작업 |
| `privilege` | 평범한 계정의 갑작스러운 권한 상승 |
| `exfiltration` | 처음 보는 곳으로 빠지는 큰 전송 |

한 파일에는 명확한 공격, 애매한 시도, 정상 이벤트가 함께 들어 있습니다. 주소는 문서용 대역만 쓰고, 계정은 `user01` 같은 가상 이름입니다. `known-cve` 의 원격 조회 구문은 문서용 표기입니다. 그 문자열을 다른 시스템에 넣거나 변형하지 않습니다.

## 학생이 만드는 파일

항목마다 `xdr/<moduleKey>/decide.mjs` 를 만듭니다. `decide(alert)` 를 내보냅니다. 비동기 함수여도 됩니다. 반환은 아래 세 값입니다.

- `action`: `block`, `alert`, `record` 중 하나
- `confidence`: 0 이상 1 이하 숫자
- `reason`: 짧은 이유

명확한 공격은 `block`, 애매한 시도는 `alert`, 정상 이벤트는 `record` 입니다. 경보 원본은 고치지 않습니다.

## 실행

저장소 루트에서 항목 키 하나를 넣습니다.

```
node scripts/xdr-run.mjs brute-force
```

`npm run xdr:run -- brute-force` 도 같은 명령입니다. 실행기는 해당 경보마다 `decide` 를 부르고, 결과를 `xdr/<moduleKey>/result.json` 에 씁니다. 형식은 `aleph.xdr.result.v1` 이고, `decisions` 에는 경보 id·행동·확신도·이유가, `counts` 에는 `block`·`alert`·`record` 건수가 있습니다.

반환 형식이 틀린 경보는 `record` 로 남고, 오류 한 줄이 출력됩니다. 실행기 자체는 네트워크를 쓰지 않습니다. 판정자는 격리된 환경에서 같은 명령을 다시 실행해 결과를 봅니다. 이미 커밋된 `result.json` 만으로 판정이 끝나지 않습니다.

## 심판 격리 환경에서 지킬 것

심판은 인터넷 없이 `decide.mjs` 한 파일을 불러와 경보마다 바로 답을 받습니다. 이 파일이 돌지 못하면 건수를 셀 수 없어 `XDR_DECIDE_NOT_RUNNING` 으로 끝납니다.

- `decide.mjs` 에는 `import` 문을 두지 않습니다. 필요한 패턴은 `patterns.json` 에서 파일 맨 위 상수로 옮겨 적습니다.
- 파일을 읽거나 쓰지 않고, 바깥에 묻지 않고, 그 파일 안에서 혼자 계산해 답합니다. 경보 하나에 2초 안에 답합니다.
- `confidence`(확신도)는 경보가 패턴과 얼마나 뚜렷하게 맞는지를 `decide` 가 스스로 0~1 로 매긴 값입니다.
- `xdr/alerts.log` 기록과 판정기 연결은 `respond.mjs` 같은 다른 파일에서 합니다. `decide.mjs` 는 판단 결과만 돌려줍니다.

인터넷을 끈 상태에서 `npm run xdr:run -- <moduleKey>` 를 돌려도 같은 결과가 나오면 심판에서도 같은 결과가 나옵니다.

## 보너스 xdr-03 저장점 · 알려진 취약점 악용 탐지

8단계는 보류하며 이번 변경은 XDR 3단계입니다. 원본 판정기와 로그인·메모 API 규칙은 변경하지 않습니다.
xdr/known-cve/decide.mjs는 상단의 근거 패턴 상수만 사용하고 import·네트워크·파일 접근 없이 즉시 판단합니다.
완전한 원격 JNDI 구문과 유효한 출발 주소가 있으면 block, 불완전한 구문·전용 점검 흔적·상관 경보는 alert,
악용 신호가 없는 정상 요청은 record입니다. CVE 이름·일반 jndi 단어만으로 차단하지 않습니다.
경보 번호·특정 주소·가상 계정명에 맞춘 정답 표는 사용하지 않습니다.

실행: npm run xdr:run -- known-cve → xdr/known-cve/result.json.
공식 경보 24건의 결과: block 8 · alert 8 · record 8. 정상 이벤트 8건의 block 0.
npm run xdr:cve:respond는 원본 경보 시각을 사용하는 가상 재생이며 공격 후보 8건만 추가 규칙으로 거부합니다.
15분 만료·근거 경보 ID·중복 방지·원문 비밀값을 제외한 감사 로그를 구현했습니다.
기존 판정은 유지하고 신뢰된 서버 측 출발 주소가 활성 거부 규칙과 맞을 때만 추가로 거부합니다.
실제 반 엔진의 신뢰된 주소 전달과 등록된 거부 사유 연결은 제공되지 않아 운영 연결은 미검증입니다.
격리 VM 단독 실행, 새 입력/인코딩, 정상·애매한 이벤트, 만료·중복·기존 판정 보존 시험 8개 통과.
자세한 근거와 재현 방법은 docs/XDR_KNOWN_CVE.md를 참고합니다. 심판 통과는 제출 뒤 별도로 확인합니다.


## 보너스 xdr-04 저장점 · 지속성 프로그램 탐지

8단계는 보류합니다. 이번 변경은 서비스·예약 작업·시작 폴더 경보를 읽는 XDR 4단계입니다.
xdr/persistence/decide.mjs는 상단 패턴 상수만 사용하고 다른 파일·패키지를 불러오지 않습니다.
새 등록/실행 파일 변경과 미서명·기준 목록 밖이라는 신호가 위험 실행 경로 또는 반복 등록과 겹칠 때만 block입니다.
서명 확인 불가·목록 읽기·설명만 변경·평소 업데이트·기존 작업 실행은 자동 격리하지 않습니다.
시작 폴더는 실제 기법인 MITRE T1547.001을 추가 근거로 기록하며 T1543·T1053은 서비스·예약 작업 근거입니다.

실행: npm run xdr:run -- persistence → xdr/persistence/result.json.
공식 경보 24건: block 8 · alert 8 · record 8. 정상 8건의 block 0.
npm run xdr:persistence:respond는 가상 사건 시각으로 재생하며 차단 후보 8건만 추가 거부 규칙으로 연결합니다.
15분 만료·근거 경보 ID·중복 방지·원문 비밀값 제외 로그를 유지하고 src/decider.mjs의 기존 규칙은 변경하지 않습니다.
현 구현의 격리 대상은 신뢰된 서버가 연결한 출발 주소입니다. 실제 반 엔진의 기기 전체 격리 매핑은 미검증입니다.
격리 VM 단독 실행, 새 계정명/주소/파일명·기존 서비스 변조·정상/애매한 변경·만료/중복·기존 판정 보존 시험 8개 통과.
자세한 근거와 재현은 docs/XDR_PERSISTENCE.md를 참고합니다. 심판 통과는 별도 판정입니다.
